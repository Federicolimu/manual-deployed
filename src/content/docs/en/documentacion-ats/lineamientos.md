description: Mandatory criteria for documenting each ATS Bitterwise module.
---

## Mandatory Guidelines

- Define the purpose of each module with clear language and no unnecessary jargon.
- Always explain the workflow as if it were for someone new to the ATS.
- Include objectives, numbered steps, referenced screenshots, and best practices per section.
- Document common errors and relevant use cases to guide daily operations.
- Maintain consistency across modules: titles, list formats, and tone should be uniform.
- Validate that examples and links work before publishing changes.

## Recommended Structure per Module

1. **Module Name** – Visible identifier within the ATS.
2. **Objective** – Role of the functionality within the recruitment process.
3. **When to Use** – Moment in the operational flow when it applies.
4. **Step by Step** – Numbered actions from access to completion.
5. **Screenshots** – Numbered images supporting the described workflow.
6. **Best Practices** – Operational tips to avoid rework and information loss.
7. **Common Errors** – Scenarios to avoid and how to resolve them.

Each new page should follow this order and, when necessary, add subsections that delve into specific features (e.g., filters, exports, or automations).
